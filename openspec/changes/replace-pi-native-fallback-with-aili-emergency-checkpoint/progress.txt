## 2026-08-01 90% hard compaction gate

The user clarified that 90% context usage is itself the last-resort safety boundary, not a fallback entered after a compression failure. The proposal now requires a per-Session pre-provider hard gate: reliable observed usage or the conservative pending-request projection at or above 90% blocks dispatch and makes the cycle's AILI emergency checkpoint mandatory. Earlier reserve-based compaction remains allowed, but the gate cannot be configured above 90% or bypassed. A request is released only after an exact persisted `fromHook:true` checkpoint and a rebuilt projection below the gate; failure leaves the request blocked and the original Session recoverable rather than sending an oversized request or using Pi-native summarization.

This requirement does not authorize BUILD or resolve the existing public provider/transport and continuation seam blockers. The one automatic plus at most three explicit retry budget remains unchanged; at the hard gate, the automatic attempt is mandatory and failure never releases the blocked request.
