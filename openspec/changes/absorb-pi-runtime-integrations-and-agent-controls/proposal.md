# Proposal: Absorb Pi Runtime Integrations and Agent Controls

## Why

The current `main` baseline already owns Persistent Agents, `pi-mcp-adapter`, a native Footer, a Web runtime foundation, and provenance tooling. It needs additive runtime work, not a replacement architecture:

- absorb `pi-notify` and experimental `pi-file-context` under immutable upstream identities;
- prevent a model argument generated by the Main Agent from silently switching a Persistent Worker away from its direct Parent's resolved model/thinking/speed state;
- produce runtime evidence for top-level Agent concurrency and separately diagnose Formal Board `EXISTING_PAIR_INVALID` without weakening its gate;
- make five core MCP capabilities available through the existing adapter lifecycle and add concise tool-routing guidance;
- add an actual Codex Fast/Priority service-tier path; and
- normalize the native Footer from real runtime state.

## What Changes

- **Upstream absorption:** lock exact immutable source identity, license, inventory, adaptation boundary, notices, provenance, SBOM, and focused tests before absorbing useful behavior from `ferologics/pi-notify` and `narumiruna/pi-extensions/experimental/pi-file-context`. Notification failures remain non-fatal. File-context retains its current TUI interaction and Git/provenance/snapshot boundaries while keeping a removable TUI adapter seam for a future shared Context Core.
- **Persistent Agent resolution and authority:** distinguish a Main Agent's `task.model` request from a user-authorized override. Without an approved override, a child inherits its direct Parent's resolved model, thinking level, and speed tier. A fresh interactive Allow-once confirmation is required before a Main-requested model change reaches child creation; no UI, dismissal, expiry, or rejection retains inheritance. User-owned instance/project/global role overrides remain authoritative. Resolved source evidence distinguishes confirmed one-shot, instance/project/user override, inherited parent, profile fallback, and runtime fallback.
- **Thinking and speed state:** propagate the direct Parent's actual supported thinking level to child `createAgentSession` calls; reject unsupported levels rather than silently downgrading or switching models. Introduce a provider-neutral Fast/Priority runtime state only where it can create documented OpenAI/Codex request service-tier evidence; unsupported provider/model combinations remain inactive/unsupported. Workers inherit their direct Parent's active supported tier.
- **Scheduling and Board evidence:** add bounded, content-free lifecycle timing for scheduling/start/first activity/completion and use it to demonstrate overlap for at least three independent top-level Agents. Preserve current nested synchronous/depth-bounded behavior. Preserve strict Board validation; diagnose and test `EXISTING_PAIR_INVALID` root causes with zero Agent allocation, file mutation, or workspace mutation.
- **MCP composition:** extend existing `pi-mcp-adapter@2.23.0` configuration/lifecycle instead of introducing an MCP manager. Configure MemPalace, CodeGraph, Context7, Playwright, and Graphify as named core capabilities with isolated failure handling, eager/keep-alive/reconnect/shutdown behavior supported by the adapter, duplicate-registration protection, and concise routing guidance. The shared user configuration remains the only active config; Graphify receives the adapter session cwd and its upstream multi-project `project_path` tool parameter resolves `<project>/.graphify-out/graph.json`, so no per-project generated config is needed. Core startup uses adapter-supported `keep-alive` only after a successful preflight for the executable; unavailable executables remain lazy/failed per server and never abort Pi. CodeGraph must remain version governed whether PATH CLI or `npx` is selected. Graphify remains distinct from CodeGraph and reports an unindexed/unavailable graph without crashing Pi.
- **Footer:** use public Pi state and existing extension status APIs to display `<provider/model> <thinking>`; normalize Codex quota as `codex <percentage> <MM/DD> <HH:mm>` without changing quota semantics; and order secondary live state as `Permission Mode · MCP x/y · HH:mm`, preserving deterministic narrow-width degradation and live updates.
- **Future-only OpenSpec:** document a future Agent Inspector as a projection of the existing Runtime Event/projection system, and a future AILI Context Core fed by the absorbed file-context behavior. Neither is implemented in this change. `pi-tool-display` remains reference-only.

## Boundaries

- Do not restore legacy subagents, replace task/hub, redesign the scheduler, enable nested parallelism, bypass Formal Board validation, create a second event/runtime/MCP manager, create `fast-gpt-*`, implement Agent Inspector, implement full Web UI, or modify `aili-workflows` unless a verified canonical contract blocks this runtime work.
- Do not commit a real Context7 secret. The local-only placeholder/config handling is separately operation-gated.
- Per the initiating request, this change is authorized to mutate repository source/tests/docs/OpenSpec, package dependencies/lockfile, third-party provenance, local MCP configuration and required local CLI installation. It does not authorize push, publication or release. A real provider request, a browser/server probe, and any user-home secret write remain separately gated.

## Change Relationships

- This is a new independent change selected by the user after current-main mapping. It modifies runtime contracts previously established by `converge-pi-runtime-mcp-memory-and-context` only where required for the new model authority, MCP lifecycle, and Footer behavior.
- It does not resume the paused foreground Pi Web work in `integrate-pi-web-ui-and-upstream-extensions`; it can only add Future OpenSpec references to that existing Web/runtime foundation.
- It supersedes no current Persistent Agent architecture and does not reactivate the legacy draft `restore-native-working-ui-and-expose-agent-model-resolution`.

## Verification Direction

Focused deterministic tests must cover model request deny/no-UI/confirmed flows, parent/profile precedence, direct-parent nested inheritance, supported-thinking behavior, speed-tier request propagation, timing overlap, Board invalid-pair zero-side-effect behavior, MCP lifecycle isolation, and Footer rendering/update/narrow layout. Operation-gated live evidence must separately prove upstream identities, installed CLI/version state, Graphify build/query, MCP reconnect/child-process cleanup, provider request tier, and three-Agent overlap.
