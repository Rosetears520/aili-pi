## Why

[已知|用户] 当前基于 `@agwab/pi-subagent@0.4.8` 的 one-shot run、外部 headless 子进程、backend 兼容 wrapper 与 `.pi/agent/runs/<run-id>/` 生命周期在真实使用中持续暴露 inline SDK、sandbox 认证/只读锁、超时和无可恢复会话等问题；用户已决定不再继续修补这套策略，而是采用 Oh My Pi（OMP）式“稳定 Agent 身份 + 持久子会话 + registry/lifecycle + 可继续通信”的整体框架。

[已知|本地与固定参考] 当前 AILI wrapper 位于 `src/runtime/subagents.ts`，普通调用被改写为 headless；固定只读参考 `.worktrees/oh-my-pi-reference`（commit `59619623e1eeb7c290649eeaf3a269284ce8adef`，MIT）证明 OMP 已有 parent-scoped child JSONL、`running → idle → parked → revived`、Agent ID、history/output addressing 和永久 Agent 模型覆盖等可借鉴契约。AILI 需要在继续保持官方 `pi` CLI 和 Pi Package/Extension 边界的前提下重建这些能力，并补充 OMP 当前 model-facing `task` schema 未公开的单次模型覆盖。

## What Changes

- **BREAKING — runtime replacement:** 移除 AILI 对 `@agwab/pi-subagent` 工具、runner、backend selector、run/attempt lifecycle 和 compatibility wrapper 的生产依赖；不再注册现有 `subagent` 工具，也不保留兼容 alias。既有 `.pi/agent/runs/` 仅作为历史用户数据保留，不自动删除、迁移或伪装成新 Agent 会话。
- **BREAKING — public orchestration surface:** 注册 AILI-owned、OMP-style `task` 与 `hub` 契约。`task` 通过 `name` 请求稳定 Agent 实例 ID、通过 `agent` 表示角色类型，支持单任务与 batch；每次 `task` 都创建新 Agent，同名请求自动分配去重 ID（如 `name-2`），继续已有 Agent 只能按稳定 ID 使用 `hub send`，不得因同名静默恢复；`hub` 提供 Agent `list`、`send`、`wait`、`inbox` 以及后台 job 的 `jobs`/`cancel`。本 change 不采用 OMP `hub` 的通用进程 daemon/start/ps/logs/restart 功能。
- 新 child 不复制 parent conversation history，只接收显式 task/context、workspace、当前 rules/skills/context files、共享资源和 approved-plan ref。为每个非隔离 Agent 创建 parent-scoped 持久 Pi Session JSONL，并维护 `running | idle | parked | aborted` registry。父会话恢复后可以重建 registry；对 idle/parked Agent 的 `hub send` 恢复原上下文，而 hard-aborted Agent 不得复活。异常进程结束时仍标记为 `running` 的未完成 turn 必须追加 durable `interrupted` outcome，并把 Agent 恢复为 parked/revivable；graceful process exit 使用相同的 interrupted 语义，尚未执行的 queued job 标记为未执行。不得自动重放可能已产生副作用的 running/queued task，下一次 `hub send` 只在同一 transcript 上启动新 turn并显式提供中断上下文；本 change 不引入退出官方 Pi 后继续运行的 daemon/detached supervisor。idle Agent 默认 420000ms（7 分钟）后自动 park，该 TTL 可配置，`<=0` 仅禁用 timer；process teardown 仍必须 park/dispose live child。
- 以稳定 Agent ID 提供模型可读的最新输出与完整 transcript addressing。task/hub 结果同时暴露 OMP-style `agent://<id>` 与 `history://<id>` URI-like refs，并提供 `hub output`/`hub history` ops 解析读取；由于官方 Pi Extension 没有已文档化的 custom URI protocol 注册 API，本 change 不宣称这些 refs 是 OS/native protocol，但不得退化成只返回一次性 run log。参考 pinned OMP 的大输出分层：完整 raw final output 写入 durable `<agent-id>.md`，完整 child Session JSONL 持久化；返回 parent 的 `SingleResult` tail 默认最多 500000 bytes/5000 lines，普通完成摘要 preview 默认 5000 chars，并显式标记 truncation；`agent://`/`hub output` 读取完整 raw artifact，`history://`/`hub history` 从 live/on-disk JSONL 生成 concise transcript，Pi-compatible hub reader 可额外提供 offset/limit，preview cap 不得删除 source artifact。
- `task` 默认 async，model-facing caller 可按调用选择 background 或 sync；非 blocking background task 立即返回 Agent/job ID，使 parent 可与一个或多个 child 并行工作，role `blocking`、显式 sync 或 async capability 不可用时同步等待，选择后台不得扩大权限。background Agent 的工具调用若需要用户批准，只暂停对应 job并把 approval request 路由到 parent UI；用户批准后恢复，拒绝则该工具失败，headless、无 UI 或 approval bridge 恢复失败时 fail closed，不采用 OMP unattended-yolo。后台任务完成结果自动回送父会话；若 parent session 暂时关闭或重启，结果必须先写入 parent-scoped durable pending-delivery ledger，并在 parent 恢复后按稳定 delivery ID exactly-once 注入，同时始终可由 `hub jobs/output` 查询。job ID 只管理一次执行，Agent ID 才是后续通信和会话恢复身份。OMP-style `hub send` 对 running recipient 在下一个安全 step boundary 注入 non-interrupting aside，不中断当前 turn；idle recipient 被唤醒，parked recipient 先 revive，live hand-off 失败才进入有界 mailbox。对同一 Agent 启动第二个并发 `task` turn 仍必须拒绝，JSONL 始终保持 single writer。`hub cancel` 对 running job 执行 hard abort，使 Agent 进入不可 revive 的 terminal `aborted`；对 idle/parked 且无 job 的 Agent 执行 release/unregister，transcript 后续保留/删除仍服从 parent artifact ownership。并发、取消、idle TTL、mailbox 上限、输出预算和恢复失败必须有显式状态，不允许假成功或静默丢失。failed live hand-off 必须写入 parent-scoped durable mailbox 并可跨进程恢复。每 Agent mailbox 上限为 100；达到上限时保留已有消息、拒绝最新消息并向 sender 返回显式 failed/overflow receipt，不采用 OMP 静默丢弃最旧消息的行为。Agent turn 默认 `maxRuntimeMs=0` 且 `softRequestBudget=0`，不设 wall-clock 或 assistant-request 上限，以支持长时间任务；manual `hub cancel`、provider/inference watchdog、tool-specific timeout、permission guard 和 bounded concurrency 仍独立生效。每个 parent session 默认最多同时运行 32 个 Agent turn，超出部分进入 FIFO queue，不得通过 async 或嵌套派生绕过该 semaphore。
- Parent session 归档时必须连同 child sessions/artifacts 一起保留或移动，并跳过仍有 active/recent nested sessions 的 cold archive；经用户确认的显式 parent delete 级联删除其 child registry/transcript/artifacts，不留下静默 orphan。单个 Agent 不提供删除 transcript/artifacts 的公共操作；`hub cancel/release` 只终止或注销 live identity，历史继续随 parent 保留。Parent fork 按 OMP 边界不共享、复制或迁移 child artifacts/live registry；fork 从空 live registry 开始，原 child 及其 transcript 仍归原 parent 所有。Fork 复制的父级 conversation entry 即使包含旧 child ref，也不使新 fork 获得该 child 的控制权或新的持久副本。
- 保留受控隔离能力，但把“会话可恢复”和“临时工作区生命周期”分开：隔离 Agent 在工作区清理后可以保留 transcript，但不得在不存在的 workspace 上恢复执行。并行写不同且互不影响的文件时默认共享 workspace；只有 write scopes 重叠，或 git index、生成目录、服务端口、数据库等共享资源可能相互影响时才 auto-isolate，不得仅因多个 Agent 都具备写工具就强制隔离。`task` 支持可选 `writeScope`（paths + shared resources）与 `workspace: auto|shared|isolated`；`auto` 只在已声明/可确定 scope 重叠时隔离，未声明默认 shared。若 runtime 在执行中检测到第二个冲突写，必须阻止该操作并返回 isolated retry，不得把已部分执行的 Agent 静默迁移；任意 bash/外部副作用无法完整静态识别，文档和状态不得声称绝对冲突检测。角色声明的 child spawns 仅在显式 `spawns` allowlist 内可用；`general` 可选择任意非自身角色，未声明 `spawns` 的专用角色不得派生 child。递归深度默认 2、可配置且硬上限为 4；不提供 OMP 的 unlimited 值，也禁止 self-recursion。top-level parent 可 async；child 派生 grandchild 时强制 sync，所有层级共享 parent depth、spawn allowlist 与 concurrency ceiling，不允许 nested background fan-out。
- 保留现有 19 个 `aili.*` role profiles，并新增 canonical selector 为 `general` 的通用 Agent 类型（总计 20 个 Agent 类型）；省略 `agent` 时默认选择 `general`，不注册 `aili.general` 或 `task` role alias。`general` 使用 AILI-owned、OMP-inspired full-worker prompt，要求聚焦委派任务、按需使用工具、仅按 spawn policy 派生专用角色并简洁返回，不复制 OMP prompt 原文。内置 20 个名称默认不被同名 project/user profile 静默 shadow；trusted project/user 只能通过按具体名称显式 opt-in 覆盖，并记录 source/provenance。`agent` 选择类型，`name` 标识可持久化实例。选择 19 个既有角色中的任一角色时必须加载该角色自己的专属 prompt，`general` prompt 不得替代或覆盖它；runtime 可以组合共享的生命周期/权限/消息协议 envelope、角色 prompt 与本次 task/context。每个角色现有的 Role、Goal、Success criteria、Constraints、Tools、Output 和 Stop 语义必须保留；只迁移 `OpenCode`/旧 Pi child identity、single-use/no-resume/`--no-session` 以及最终获批 spawn policy 所要求的 runtime adapter 条款。19 个既有角色的 prompt、工具/能力上限与 provenance 继续由 `manifests/roles.json` 和生成链拥有，迁移后必须更新并验证 source/profile hashes。持久 Agent 不锁定创建时的 role prompt snapshot：profile 更新后，其下一个 turn/revive 必须自动采用最新有效 prompt/hash；不得改写已在执行的 turn，且 transcript/registry 必须记录每个 turn 实际采用的 prompt version。通用 Agent 不设独立静态工具白名单，其有效工具集合继承父 Agent 当前 active tool ceiling，并与当前可用 capability 取交集；调用方只能继续缩窄，未来父级新增工具自动可用。所有类型继续执行 `pi-permission-modes`、credential/auth/private-key path hard denial、project trust、外部写入确认和递归深度限制；继承不得扩大父级文件、网络或工具权限。
- 新增 role-level 与 stable-instance-level 永久模型覆盖和单次调用模型覆盖。有效优先级固定为：`task` 单次/单项 `model` > instance override > trusted project role override > user-global role override > Agent frontmatter `model` > parent active/fallback model。instance override 随 child registry/session 持久化；role override 同时支持 official Pi 的 project 与 user-global settings scope，project 仅在 trust 后生效。用户通过显式 command/TUI/manual config 可以修改永久配置；Agent/model-facing `task`/`hub` 只能请求变更，并且每次都必须获得用户交互确认，无 UI/headless 或拒绝时 fail closed 且配置 bytes 不变。单次 override 只影响该次 Agent turn，不写回任何永久配置、不修改 role profile；同一 Agent 后续未传 `model` 时重新使用已配置的永久模型。
- 保持官方 Pi runtime、`pi` CLI 和单一 AILI Extension entry，不引入 `omp` CLI 或整套 Bun/@oh-my-pi runtime。可选择性改写或复用 OMP MIT 代码时，必须固定 source revision、记录 copied/adapted symbols、保留 license/NOTICE/SBOM/provenance，并用本仓库契约测试证明行为；未审计代码只可作为参考。
- 更新 capability registry、doctor、README、role/skill adapter、生成/发布证据和测试，使 `subagent.dispatch` 映射到新 runtime；canonical `aili-workflows` 中现有 fresh/single-use/no-resume/no-recursion 规则的语义修订属于独立跨仓写入，必须另行取得精确批准。

## Impact

预计移除 `package.json`/lockfile 中的 `@agwab/pi-subagent` production dependency，并替换 `src/runtime/subagents.ts`、runtime registry/doctor/capability/provenance、Agent profile adapters、README 与现有 subagent unit/integration/live fixtures；预计新增 AILI-owned task/hub、Agent registry/lifecycle、child Session persistence/rehydration、message/job coordination、history/output resolver、1 个通用 Agent profile、model override config 与 disposable-session fixtures。dependency/lockfile mutation必须在 BUILD 前获得单独精确批准。

本 change 与以下未归档合同存在显式关系：

- supersede `openspec/changes/fix-subagent-inline-sdk-compatibility/` 的后续 live/default-backend目标；新 runtime 不再以修复旧 inline/headless selector 为目标；
- supersede `openspec/changes/create-aili-pi-distribution/` 中由 `@agwab/pi-subagent`、fresh/single-use/no-resume/no-recursion 定义的 subagent 条款，但不改变官方 Pi、单一 Extension、Linux、权限和凭据边界；
- invalidate `openspec/changes/support-pi-0-82-0/` 中“保持 `@agwab/pi-subagent@0.4.8`”的 subagent-specific 设计/任务；该 direct dependent 必须在本 change 的 design/spec 确认后同步修订并重新验证。

Harness evolution primary component 为 `subagent-config`，secondary components 为 `workflow-pattern`、`docs/protocol`、`install/setup`。主要回归风险是父/子会话串线、并发双写、park/revive race、消息丢失、模型 override 污染永久配置、权限扩大、孤儿 job/session 和旧 skill 继续强制 single-use。验证触发器必须至少覆盖 disposable HOME 中的 create→yield→park→process teardown→parent resume→revive、parallel ID collision、same-ID concurrency rejection、hard-abort、isolated transcript-only、model precedence/config byte-stability、credential/tool ceiling、async delivery 和旧 runtime 完全未注册。

Rollback 必须作为一个原子依赖/运行时恢复包：恢复精确 `@agwab/pi-subagent` pin、旧 wrapper/registry/manifests/tests 与对应 lock/provenance identity；不得只恢复工具名而留下两套 session owner 或同时注册新旧 runtime。

本 proposal 只授权 OpenSpec DEFINE artifact 写入，不授权生产代码修改、dependency/lockfile mutation、复制 OMP 源码、`aili-workflows` 写入、真实 provider/sandbox probe、用户 `~/.pi/agent` 修改、commit、push、publish 或 release。最终 design/spec/tasks/test-plan 必须 coherent/strictly valid，并由用户明确接受最终 `test-plan.md` 后才能进入 BUILD。
